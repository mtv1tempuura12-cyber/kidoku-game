# 既読の向こう

初めてマッチした航平として、架空の相手「みずき」と夜通し会話するチャット型サスペンスです。スマートフォンでは画面全体をチャットに使い、PCでは中央にスマートフォン幅の画面を表示します。

## 遊び方

`index.html`をブラウザーで開き、「既読をつける」を押します。選択肢はありません。返信欄に自分の文章を入力して送信すると、相手の「入力中」表示を経て、一文字ずつメッセージが現れます。Enterで送信、Shift＋Enterで改行できます。右上の「×2」で表示を早められます。

会話には13の場面があり、質問や寄り道への返信によって往復数が増えます。最初は日常的な話を重ね、後半で別のチャット、予約ページ、仮決済、身分証の話が出ます。日常の話題、質問、唐突な性的発言への境界線を示す反応、同意・拒否・連絡の終了などを端末内で判定し、文面を分岐させます。未知の文章や短い返事でも物語を進めます。質問・寄り道による追加の往復は各場面で最大1回です。会う約束やリンク・支払い・身分証の要求を断った場合は、相手が引き下がる別の展開から結末へ進みます。別の店・当日払い・公式窓口での確認という提案にも分岐します。同意しないと先に進めない箇所はありません。どの文章も理解できるAIチャットではなく、用意した会話パターンへ分岐する静的ゲームです。結末は3種類で、最後に100点満点の結果と主な場面を表示します。

登場人物、アプリ、店名、ID、URLはすべて架空です。チャットは架空のマッチングアプリ「mellow」から、起動画面を挟んで別デザインの「talo」へ切り替わります。予約URLを押すとゲーム内ブラウザーでローカルの `reservation.html` を実際に読み込みます。表示される `.example` ドメインへの通信はしません。予約確認・架空カードでの仮決済・架空の証明書提出を操作でき、判断は会話側の結末にも反映します。チャットへ戻ると会話は保持されています。`.example` は[IANAの特別用途ドメイン](https://www.iana.org/assignments/special-use-domain-names)です。入力した文章は送信・保存されず、ページを再読み込みすると消えます。実際の個人情報は入力しないでください。

相手役のアイコン `assets/mizuki-avatar.png` は内蔵の画像生成ツールで作成しました。生成時の指定は「架空の日本人成人女性、自然なカフェでのプロフィール写真、正面を向いた親しみやすい表情、円形に切り抜ける構図、文字・ロゴ・実在人物への類似なし」です。

## GitHub Pagesで公開する

1. GitHubに公開用リポジトリを作成します。
2. `index.html`、`style.css`、`script.js`、`reservation.html`、`reservation.css`、`reservation.js` と `assets/` フォルダをリポジトリのルートに置いてコミットします。
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment** の **Source** を **Deploy from a branch** にし、公開ブランチ（例：`main`）と **`/(root)`** を選んで保存します。
5. Pagesに表示された公開URLを開き、スマートフォンとPCで最後まで操作して確認します。

既存のリポジトリなら、これらのファイルと `assets/` を `/docs` に置き、Pagesの公開フォルダを **`/docs`** に設定します。詳しくは[GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)を参照してください。

この物語は実際の相手がサクラや業者かどうかを判定するものではありません。内容の参考：[消費者庁「サクラサイトトラブル」](https://www.caa.go.jp/policies/policy/consumer_policy/caution/internet/trouble/sakura.html)、[国民生活センター「SNSから有料メール交換サイトに誘導された」](https://www.kokusen.go.jp/t_box/data/t_box-faq_qa2021_33.html)。

## 動作の補足

予約画面はスクリプト実行だけを許可したiframe内に表示します。親ページは、そのiframeから送られた所定の模擬操作だけを受け付けます。フォーム、アップロード、実決済、外部API、端末への永続保存は使用しません。会話は定型文と話題判定によるため、未知の話題や複雑な文脈の理解には限界があります。
